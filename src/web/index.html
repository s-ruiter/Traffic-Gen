Welcome to Traffic-Gen

Traffic-Gen generates realistic user traffic from this LXC to monitor and test a FortiGate: Application Control, web filtering, SD-WAN, antivirus and IPS efficacy, and bandwidth. Everything is controlled from this web interface.

Traffic test

Realistic user traffic from many source IPs: Netflix, YouTube, Teams, Microsoft 365, Facebook and more. Compare it with the FortiGate logs and dashboards.

Security efficacy

Harmless EICAR/WICAR files and botnet-style DNS lookups. The tool counts what the FortiGate blocks and what it misses, and shows the detection rate.

Throughput

A sender and a receiver on two networks, with the FortiGate in between: bandwidth, packet loss, jitter, latency (UDP, TCP, RFC 2544) and connections per second.

Getting started

  1. Network: add a source network on eth1 (first IP, number of IPs, FortiGate gateway) and click Apply.
  2. Traffic mix: choose which traffic to generate, then start the test and follow the results live.
  3. Throughput (optional): add a third interface (eth2) for the receiver, then measure bandwidth, packet loss and connections per second.

Traffic mix

Decide which kind of traffic occurs and how often. A weight of 0 disables a group.

Security tests. Malware test only uses standard, harmless test files (EICAR, WICAR); a download that the FortiGate lets through counts as missed. IOC / botnet behaviour only sends DNS queries (DGA patterns, DNS tunnelling, dynamic DNS, mining pools) and, on request, bare TCP connects, without data or downloads. Both are off by default; only enable them on networks where you are allowed to test this. The extra IOC switches are under Settings.
Presets only move the sliders; the mix is saved when you click Save or start the test.

Throughput

Measure bandwidth, packet loss and connections per second through the FortiGate: a sender on a source network talks to a receiver on a second network.

Path

Traffic flows from the sender (a source network on eth1) through the FortiGate to the receiver (the third interface, eth2). The receiver is set up here, not on the Network page; only the sender network is configured there.

Sender — uses the first IP of a source network
Receiver — a virtual interface on the third NIC, only while a test runs
The receiver gateway is the FortiGate's own address in the receiver network (the FortiGate interface or VLAN interface connected to eth2). The sender's gateway comes from the Network page.
What the self-test does. Sender and receiver both run inside this LXC and talk to each other over 127.0.0.1 (the loopback interface). The packets never leave the LXC: they do not reach a network interface, the Proxmox bridge or the FortiGate. Use it to check that the tool works and to see the highest rate this LXC can generate and receive (limited by its CPU cores and the Python engine). That tells you whether a limit in a real test comes from the tool or from the network. Do not use it to judge the FortiGate, your bandwidth or packet loss: loss is normally 0% and latency is tiny by design. For real results choose Isolated (via FortiGate) and a receiver interface.
